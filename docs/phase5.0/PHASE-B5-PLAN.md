> **状态：仅计划提交，未开始任何 B5 实际开发。**
> 依据：B4 最终验收通过（`docs/phase5.0/PHASE-B4-FINAL-ACCEPTANCE.md`）
> 冻结基线：`5339589f0577fa0fd0a70476fa19ead7001fe27a`（B4）· 分支 `phase5.0-a`

## 1. 目标与非目标

### 1.1 目标（B5 全部完成时）

1. 在 **真实 APK（WebView + Capacitor + Android 系统栏）** 环境中验证并修正 edge-to-edge Insets 适配；
2. 验证并修正**系统字体缩放 130%/150%** 下的布局、底栏与弹窗；
3. 复核 B3 键盘/弹窗与 B4 材质在 APK 内不被破坏；
4. 完成真机性能、低端 WebView 降级路径与全量回归；
5. 产出一份可人工验收的 **B5 验收包**（APK 测试包 + 证据 + 报告）。

### 1.2 非目标（明确排除）

| 排除项 | 说明 |
|---|---|
| 新视觉设计 / 新功能 | B5 只做**系统级适配与验收**，不再改材质语言 |
| 合并 `main` / 打 Tag / 正式发布 APK | 需单独批准并另立指令 |
| 结构性重构 | 不改数据层、不改 CAS/多标签机制、不改路由 |
| PWA 行为变更 | 仅回归验证（须保持 14/14） |
| 扩大验收范围 | 设备以 vivo X200s 为主；低端机仅做降级路径验证 |

## 5. 风险与应对

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| 1 | 构建环境不可复现（SDK/Gradle 版本） | B5.1 阻塞 | B5.0 先做环境审计；锁定版本并记录 |
| 2 | Insets 在 APK 与浏览器行为不同 | 需返工 | 以 `dumpsys window` 真实值 + app 内读数为双基准，逐项对照 |
| 3 | 三键导航/横屏组合遗漏 | 遮挡缺陷 | 矩阵强制覆盖，缺一项不通过 |
| 4 | 字体缩放导致底栏高度变化连锁 | 布局回归 | 以 B2/B3 套件为回归门 |
| 5 | 低端 WebView 掉帧 | 体验风险 | 降级路径 + 明确可接受阈值 |
| 6 | 测试 APK 与发布包混淆 | 误发风险 | 严格区分 `*-test.apk` 与发布包；发布构建需单独批准 |
| 7 | 修复越界（改动材质/业务） | 回归面扩大 | 每阶段限定文件白名单，超范围需重新申请 |
