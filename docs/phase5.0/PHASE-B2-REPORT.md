## 2. 四项 P0 修复前后对比

### P0-1 · Insets 初始化时序（推送早于 JS 钩子）

| | 修复前 | 修复后 |
|---|---|---|
| 机制 | `onCreate` 推送一次；此时 `window.__lgApplyInsets` 未定义（实测 JS 钩子在 t≈1534ms 才可用） | JS 启动即 `requestInsets()` → 原生**无条件重发缓存**；带 6 档重试（0/120/300/700/1500/2600ms） |
| 验证 | 模拟"原生迟到 800ms 回包" | **✓ 仍被应用**：`safe={top:24,bottom:48}`；启动请求次数 **2** |

### P0-2 · 页面重载后 Insets 失效

| | 修复前 | 修复后 |
|---|---|---|
| 机制 | 原生去重锁 `lastTop…` 阻止相同值重发；重载后 JS 变量清空 → 永久为 0 | 重载后 JS 重新拉取（`pageshow`/启动即拉） |
| 验证 | — | **✓ 重载后请求数 2 → 4，`safe` 恢复 `{24,48}`**；回前台（visibilitychange）请求数 4 → 5 |

### P0-3 · 底部安全区重复计算（"遮挡任务卡片"）

| 场景 | 修复前（B1 实测） | 修复后（B2 实测） |
|---|---|---|
| 三键 48dp | 导航高 112 + 偏移 60 = 占用 172；预留 144 → **遮挡 28px** | navH 58 + 偏移 60 = 118；预留 138 → **遮挡 −20px（呼吸 20px）** |
| 三键 + 字体 150% | 占用 200；预留 144 → **遮挡 56px** | navH 86 + 偏移 60 = 146；预留 166 → **遮挡 −20px** |
| 手势导航 | 预留 96 / 占用 76 → 余 20px（正常） | 预留 90 / 占用 70 → **余 20px** |
| 无 Insets | 余 20px | 余 20px |

公式（单一真源）：
```
占用 = --fd-nav-h + --fd-nav-gap + safe-bottom + ime
预留 = --fd-nav-h + 2×--fd-nav-gap + safe-bottom + ime + 8px
⇒ 呼吸空间恒 = --fd-nav-gap + 8px = 20px（与 safe/字体/ime 无关）
```

### P0-4 · 系统状态栏 / 导航栏遮挡应用内容

| 指标 | 修复前 | 修复后（safe-top 24 / safe-bottom 48） |
|---|---|---|
| 头部 top | **12px**（被状态栏 24–30dp 覆盖） | **36px** = safe-top + 12 ✓ |
| 底栏底边距屏幕底 | **12px**（被系统导航栏 48dp 覆盖） | **60px** = safe-bottom + 12 ✓ |
| 头部/底栏左右 | 仅 `inset-x-3`，忽略横屏侧栏 | 左右 = safe-left/right + 12（横屏实测 left=60/right=12） |

![修复前 / 修复后（390×844，三键 48dp，滚动到底）](phase-b2-evidence/compare-3button-bottom.png)

左：修复前（B1 采集）——最后一屏任务被应用导航压住 28px，导航沉在系统导航区里。

## 7. 测试基础设施修正（**非产品代码**，必须知悉）

`e2e-a11y.mjs` 的"多浮层"用例此前依赖"打开导入预览后 900ms 仍处于未保存状态"，而设置页自动保存防抖只有 180ms → dirty 被冲掉 → 确认框不出现 → Enter 直接导入空备份，导致 5 项连锁失败（含 K5 习惯打卡）。

**A/B 证据**：把产品代码回退到 B2 之前的 `048a091` 再跑同一套件，**同样是 30/35、同 5 项失败** → 证明与 B2 改动无关，是套件自身的时序缺陷。

修正方式：只在点击"覆盖导入"之前重新制造一次未保存修改（意图不变：验证"有未保存修改时二次确认"），未放宽任何断言。修正后连续 3 次 **35/35**。
